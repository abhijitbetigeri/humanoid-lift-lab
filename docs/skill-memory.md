# ASPIRE-inspired validated skill memory

This is a small local memory layer for Lift Lab, inspired by ASPIRE's practice of
retaining validated repairs as reusable guidance. It does not import ASPIRE,
implement its full search procedure, or establish a new robotics result.

## Implemented boundary

`loop/skill_memory.py` uses only the Python standard library. Admission is an
explicit host operation; generated critiques and failed trials are never promoted
automatically. It checks:

- the run config explicitly declares `stub: false` and `split: development`;
- a host-produced validation manifest names `sim.trial`, the development split,
  and the independent physics scorer;
- the controller and the named environment files match validation hashes;
- every referenced result and trajectory matches its recorded hash;
- each referenced result has `success: true` and no failure reason.

Retrieval is opt-in (`enabled=False` by default), read-only, deterministic, and
restricted to the exact environment hash. Title/tag token overlap ranks matching
skills; stable skill IDs break ties. Complete entries are included only if they
fit the character budget, so guidance is never silently cut in half. Relevance
is a simple lexical heuristic, not a learned semantic ranker.

Evidence files are rehashed before retrieval. Missing or modified evidence fails
closed. Writes use atomic replacement; one process should own the memory writer.
The module is not a concurrent database.

## Trust and scientific limits

The host must independently run and score the controller before creating the
validation manifest. Do not let Argon supply or edit that manifest. Checking a
JSON field named `independent-physics-scorer` is provenance validation, not proof
that a simulator ran. This module does not replay trajectories or invoke the
scorer. Hashes detect changed artifacts relative to a trusted manifest; they do
not prevent an actor with write access from fabricating the entire record.

A successful controller does not prove every sentence of its verbal guidance is
correct or causally responsible for success. Review the proposed skill, then
measure memory-enabled versus memory-disabled behavior on held-out conditions.
Describe entries as guidance associated with successful development evidence,
not as proven physical laws. Keep failed attempts in the experiment log outside
this validated skill store.

## Manifest contract

The existing loop's config does not yet declare the split. An evaluation host
must write a separate explicit config or extend the config with the split.
Legacy artifacts lacking it are intentionally rejected.

`validation.json`, generated by the trusted evaluation host:

```json
{
  "backend": "sim.trial",
  "split": "development",
  "validator": "independent-physics-scorer",
  "controller_sha256": "<hash of evaluated controller>",
  "environment_sha256": "<environment_hash(environment_files)>",
  "trials": [
    {
      "result_path": "trials/m10/result.json",
      "result_sha256": "<hash>",
      "trajectory_path": "trials/m10/traj.npz",
      "trajectory_sha256": "<hash>"
    }
  ]
}
```

Paths in the validation manifest are relative to its directory, or absolute.
Admission stores absolute artifact paths, so keep the evidence directory stable
and read-only for a frozen experiment. Cross-machine relocation requires a
separately verified rebasing/export mechanism; it is not implemented here.

The host should also retain seed, mass, repetition, scoring version, model ID,
API parameters, and creation time in the surrounding experiment manifest. These
are experiment-level metadata, not inferred by this memory module.

## Host integration example

```python
from loop.skill_memory import SkillMemory, environment_hash

files = {
    "sim/humanoid_api.py": "sim/humanoid_api.py",
    "sim/trial.py": "sim/trial.py",
    "sim/g1/scene_lift.xml": "sim/g1/scene_lift.xml",
    "sim/g1/g1_with_hands.xml": "sim/g1/g1_with_hands.xml",
}
# Include any other configuration, included XML, and assets affecting physics.
memory = SkillMemory("runs/development/skills.json")
skill_id = memory.admit(
    title="Staged payload grip",
    guidance="<reviewed general rule associated with the validated repair>",
    tags=["grip", "payload", "lift"],
    controller_path="runs/development/round_2/controller.py",
    config_path="runs/development/config.json",
    validation_path="runs/development/round_2/validation.json",
    environment_files=files,
)
context = memory.retrieve(
    "payload grip lift", environment_sha256=environment_hash(files),
    enabled=True, max_chars=3000,
)
# Supply context as clearly labelled development guidance in a future prompt.
# The no-memory condition calls retrieve(..., enabled=False), yielding "".
```

No automatic integration with `loop/run_loop.py` is included. Add an explicit
memory toggle and record store SHA256, retrieved skill IDs, retrieval query,
character budget, and actual prompt text in each run before comparing conditions.

## Evaluation use

Follow `docs/evaluation-plan.md`. Build memory only from the designated real
simulation development partition, then freeze the store **and all referenced
evidence** before running comparisons. Use the same snapshot across repetitions.
Held-out observations may inform the evaluated controller only as explicitly
allowed by the protocol; they must never enter persistent skill memory.

Compare matched video+telemetry loops with and without memory, recording the
extra prompt tokens and cost. Do not claim a memory benefit from lower training
error alone. The current implementation has no validated production entries;
unit tests use explicit fixtures and make no robotics performance claim.

## Verification

```bash
python3 -m unittest discover -s tests -p test_skill_memory.py -v
```

Tests cover opt-in/no-memory behavior, persistent deduplication, stub and split
rejection, independent-validator requirements, changed controller/environment
provenance, failed-result rejection, artifact tampering, bounded deterministic
retrieval, and read-only retrieval.
